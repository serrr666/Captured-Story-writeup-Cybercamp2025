# Captured Story — разбор задания CyberCamp

## Ответы

| Вопрос | Ответ |
|---|---|
| IP начала атак | `10.0.1.50` |
| Техника компрометации первой машины | T1190 — Exploit Public-Facing Application |
| IP C2 | `10.0.1.247` |
| Созданный пользователь | `Fiona` |
| Протокол бокового перемещения | WinRM |
| Файл на второй машине | `watch_movie.ps1` |
| Цвет зонта | Жёлтый |

## Ход расследования

### 1. Первоначальная активность

Источник `10.0.1.50` исследовал Linux-хост `192.168.1.12` с Wing FTP. Обнаружен массовый перебор FTP-паролей на TCP/21. В предыдущем анализе успешный FTP-вход не найден: перебор не считается подтверждённым способом первоначального доступа.

### 2. Компрометация Wing FTP

Первоначальный доступ связан с веб-интерфейсом на TCP/80. Запросы к `/loginok.html` содержали NULL-байт и внедрение Lua-кода, соответствующие CVE-2025-47812. Сигнатура Suricata Wing FTP Server NULL-byte Authentication Bypass поддерживает идентификацию попытки; сама сигнатура не доказывает успешную эксплуатацию. В сохранённом анализе успех подтверждается выполнением команд и последующей активностью жертвы. Проверка текущего пользователя возвращала root.

Это соответствует T1190: эксплуатация доступного по сети приложения.

### 3. Управление через C2

Жертва загрузила `ftp_update.sh` с `10.0.1.152:80` по HTTP. Скрипт устанавливал обратную оболочку к `10.0.1.247:443`. В сохранённом разборе этот обмен представлял открытый командный поток, несмотря на порт 443.

Таким образом, `10.0.1.152` — сервер раздачи скриптов, а `10.0.1.247` — адрес управления и приёма похищенных данных.

### 4. Закрепление

В командном потоке обнаружено создание локального пользователя `Fiona` и установка ему пароля. После завершения обратной оболочки появилось SSH-соединение от `10.0.1.247` к `192.168.1.12:22`.

Использование Fiona для этого SSH-сеанса вероятно по времени событий, но не подтверждено содержимым зашифрованного SSH-трафика.

### 5. Боковое перемещение

Linux-хост `192.168.1.12` подключился к Windows-хосту `192.168.1.1:5985`. Признаки WinRM: порт назначения, User-Agent Ruby WinRM Client и NTLMSSP-обмен с именем `admin`.

Ответ на вопрос задания — WinRM. SSH относился к повторному доступу на первую машину.

### 6. Скрипт на Windows

Windows-хост запросил `/watch_movie.ps1` у `10.0.1.152:80`. User-Agent содержал WindowsPowerShell. Это HTTP-загрузка, а не FTP.

### 7. Эксфильтрация

По сохранённому разбору деобфусцированного скрипта, он читал `C:\Top_Secret_Image.png`, преобразовывал байты повторяющимся XOR-ключом `ThisIsMySwamp` и передавал их в шестнадцатеричном виде на `10.0.1.247:80`.

Из потока восстановили PNG. На картинке изображён осёл в солнечных очках на пляже под жёлтым зонтом. Цвет проверен непосредственным просмотром восстановленного изображения.

## Цепочка атаки

Разведка → эксплуатация Wing FTP → root-доступ → обратная оболочка → создание Fiona → SSH к Linux → WinRM на Windows → загрузка PowerShell → сбор и кража PNG.

## Ограничения доказательств

Этот документ составлен по сохранённому предыдущему анализу PCAP и выпискам участника. При составлении документа повторное независимое исследование пакетов не проводилось. Восстановленная картинка просмотрена непосредственно. Не установлены номера пакетов и TCP-потоков для каждого вывода. Большой объём HTTPS к CDN сам по себе не доказывает вредоносность. Имя учётной записи в последующем SSH-сеансе не установлено.
